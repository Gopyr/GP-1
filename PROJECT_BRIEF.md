# GP-1 project brief

## User intent

GP-1 is the new, substantially more polished successor to `Advanced-Layer-7-Stress-Test-Tool` and is intended to become the **main showcase project** linked from the Gopyr profile. It should look and feel like the strongest repository in the portfolio, not like a generic utility or a narrow documentation exercise.

The project must have a clear identity, meaningful GitHub tags, serious documentation, real experiments, reproducible test data, and an honest explanation of how far the system was tested and what impact was observed in controlled environments.

## Product direction

GP-1 should present a technically ambitious HTTP performance and resilience research toolkit with a professional CLI, structured results, repeatable experiments, visual or tabular evidence, and a roadmap that makes the project look alive and worth studying.

The implementation must remain bounded to systems owned by the operator or explicitly authorized test environments. Safety boundaries should protect the project and its users without replacing the project's identity with a generic safe-load-test template.

## Profile role

The profile README should feature GP-1 as the **primary project** and describe it before the smaller web, Android, Discord, and payment prototypes. The repository description, topics, README opening, experiment results, and profile link should all reinforce the same flagship positioning.

## Acceptance criteria

A visitor should understand within the first screen that GP-1 is the main technical project, what problem it investigates, how its experiments are run, what data has actually been measured, and which claims are intentionally not made. The repository should be credible because its evidence is specific, reproducible, and honest—not because it uses inflated language or decorative AI-generated copy.
